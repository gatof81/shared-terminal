Sesión nueva

Todo lo demás es opcional. En las pestañas de arriba podés agregar un repo, variables de entorno, puertos expuestos o comandos del ciclo de vida.

Clona un repo en el workspace antes de que corra tu comando postCreate. Dejá Destino vacío para clonarlo en la raíz del workspace (la reemplaza). Las credenciales PAT y SSH se guardan cifradas con AES-GCM y nunca se devuelven.

Las variables planas se guardan tal cual; las secretas se guardan cifradas con AES-GCM y nunca se devuelven. Los nombres siguen la convención de la shell POSIX (mayúsculas, dígitos y guion bajo; empiezan con una letra o _).

Nombre Valor Tipo Quitar

Puertos del contenedor publicados como p<puerto>-<sessionId>.<base>. Los puertos públicos no verifican la cookie st_token (para webhooks o callbacks de OAuth): activalo solo para receptores que esperan llamadas de cualquiera.

Puerto del contenedor Público

Esto corre durante el bootstrap de la sesión. El tiempo total de todas las etapas tiene un tope de 10 minutos.

Identidad de Git

Configura user.name / user.email de forma global en el contenedor de la sesión, para que los commits salgan con la identidad correcta.

Dotfiles

Se clonan en ~/dotfiles antes del comando postCreate. Usan las mismas credenciales que el repo principal de arriba (PAT o SSH). Si el clon sale bien, el script de instalación (opcional) corre dentro del árbol clonado.

Configuración inicial del agente

Los dos archivos se escriben tal cual en ~/.claude/ para que la CLI de Claude arranque configurada. settings.json tiene que ser JSON válido.

Comandos del ciclo de vida
Recursos

Límites por sesión. Los campos vacíos usan los valores por defecto de la instalación (2 núcleos / 2 GiB / sin detención automática). Rangos: CPU 0.25–8 núcleos, memoria 256 MiB–16 GiB, inactividad 1 minuto–24 horas.

Detiene el contenedor después de N de inactividad. Los archivos del workspace se conservan; abrir una pestaña lo vuelve a poner en marcha.

Puertos privilegiados

Los procesos del contenedor no pueden escuchar en puertos menores a 1024 sin CAP_NET_BIND_SERVICE. Activalo para otorgar exactamente esa capacidad (y solo esa) en docker run, así la pestaña Puertos acepta valores como 80 o 443. El resto de las capacidades del contenedor siguen quitadas.

Códigos de invitación

Compartí un código de invitación para que alguien pueda crear una cuenta. Cada código se usa una sola vez.

Plantillas

Configuraciones de sesión reutilizables. Usá una para completar una sesión nueva; los valores secretos no se guardan y se vuelven a pedir al usarla.

Puertos expuestos

Exponé un puerto en el que escucha tu sesión. Los cambios se aplican enseguida, sin reiniciar la sesión. Los puertos públicos no piden autenticación (cualquiera con la URL llega); usalos solo para webhooks o callbacks de OAuth. La ruta de disponibilidad (opcional) se consulta durante el bootstrap para avisar cuándo responde el puerto: es informativa y nunca hace fallar la sesión.
