# Project Chat — propuesta de UX

Estado: borrador. Se apoya en el shell v2 ([ui-unificada.md](../ui-unificada.md) §5) y en sus
invariantes: **el Terminal nunca se redimensiona ni se desconecta por un cambio de vista**; overlays
con `inert`; `textContent` sin `innerHTML`; el router es el estado.

## 1. Navegación

```
Sidebar
├── Proyectos            ← nuevo
│   └── <proyecto>       → #/projects/<pid>            (chat del proyecto)
│                          #/projects/<pid>/agents/<aid> (panel del agente)
└── Sesiones             ← como hoy
    └── <sesión>         → Terminal · Files · Git · Chat (sin cambios)
```

El panel de un agente enlaza a su sesión (`#/sessions/<sid>/chat/<cid>`), donde viven el hilo
completo, el Terminal y el Control Directo. No hay una segunda vista de conversación.

## 2. Chat del proyecto (desktop)

```
┌ Proyecto: tienda ─────────────────────────────────────────┬ Agentes ─────────────┐
│ ── hoy ──                                                 │ ● @backend  trabajando│
│ Vos → @backend @frontend                                  │ ○ @frontend esperando │
│   Agreguen validación de email en el registro.            │ ◌ @docs     sin canal │
│   @backend  ✓ recibido · trabajando…                      │                       │
│   @frontend ✓ recibido · terminó  ▸ resultado             │ Pendiente de aprobar  │
│                                                           │  @backend → @frontend │
│ ┌ @frontend · resultado ───────────────────────────────┐  │  "¿Me pasás el schema?"│
│ │ Agregué la validación en RegisterForm.ts …  Ver hilo  │  │  [Aprobar] [Rechazar] │
│ └──────────────────────────────────────────────────────┘  │                       │
│ @backend · avance: "Encontré el validador en users.ts"    │                       │
│ ▸ 3 eventos técnicos                                      │                       │
├───────────────────────────────────────────────────────────┴───────────────────────┤
│ [@backend ×] Escribí un mensaje…                                    [Enviar]      │
└───────────────────────────────────────────────────────────────────────────────────┘
```

Tres clases de elementos, visualmente distintas:

| Clase | Ejemplos | Presentación |
| --- | --- | --- |
| Coordinación | mensajes humanos, `chat_send` entre agentes, aprobaciones | burbujas con autor y destinatarios |
| Resultado | tarjeta del `turn_end` aceptado; `chat_post kind=result` | tarjeta con borde, "Ver hilo", "Copiar" |
| Técnico | transiciones de entrega, runtime registrado/retirado, `unconfirmed`, límites | colapsado por defecto ("▸ N eventos técnicos"); siempre visible si es un fallo |

## 3. Estados de entrega en palabras

| Estado | Chip | Texto de ayuda |
| --- | --- | --- |
| `awaiting_approval` | ⏸ espera tu aprobación | "Lo pidió @x. Nada se envía hasta que lo apruebes." |
| `queued` | ⏳ en cola | "@x está trabajando / desconectado. Se envía cuando esté en su prompt." |
| `transporting`/`transported` | ↗ enviando | (transitorio) |
| `uncertain` | … esperando confirmación | "El agente puede tenerlo en cola. No enviamos nada más a @x hasta saberlo." (sin botón de reenvío) |
| `accepted` | ✓ recibido | "Claude lo tomó como turno en la conversación <título>." |
| `completed` | ✓ terminó | tarjeta de resultado |
| `ended_unattributed` | ✓ terminó · sin respuesta propia | "El turno incluyó también <texto del Terminal / una notificación de tarea / otro mensaje>. No mostramos su informe como respuesta a este mensaje." + Ver hilo |
| `interrupted` | ⚠ interrumpido | "El turno terminó sin informe (error, salida o parada)." |
| `unconfirmed` | ? sin confirmar | "Pudo haber llegado o no. No lo reenviamos para no duplicarlo. Mirá el hilo o usá Control Directo." + [Reenviar como mensaje nuevo] + [Copiar texto]. Control Directo nunca se pre-rellena |
| `unconfirmed{relay-loss}` | ? sin confirmar · puede haberse ejecutado | "Se perdieron eventos del agente: pudo haberlo hecho sin que lo viéramos. Mirá el hilo o el Terminal antes de reenviar." |
| `failed` | ✕ no enviado | motivo concreto (expiró, cola llena, agente quitado) |
| `denied`/`cancelled` | — | quién y cuándo |

"Reenviar" crea siempre un mensaje nuevo (nuevo `clientMessageId`) y lo dice.

## 4. Composer del proyecto y menciones

- Los destinatarios son **chips** (`to` explícito); escribir `@` abre el selector de agentes del
  proyecto. El texto no se analiza para menciones en el servidor.
- Sin destinatario el botón Enviar se deshabilita con "Elegí al menos un agente".
- El borrador se conserva ante cualquier error que no sea 202 (como el composer 3.2).
- Límite M1 visible al acercarse (contador).

## 5. Roster y presencia

| Presencia | Fuente | Ícono |
| --- | --- | --- |
| trabajando | estado `running` de la conversación del runtime | ● |
| esperando input | `waiting_input` verificado | ○ |
| esperando permiso / terminal | `waiting_permission`, `needs-terminal` | ⚠ "necesita el Terminal" |
| desconectado | contenedor parado o sin `claude` | ◌ |
| sin canal | runtime no registrado: flag ausente, política, versión no validada | ◌ + motivo |
| canal sin respuesta | runtime `degraded`: una entrega sin evidencia con el agente en su prompt (posible kill switch) o `source` ausente | ⚠ + "Probar el canal otra vez" (sólo reactiva para el siguiente mensaje en cola) |
| ambiguo | dos runtimes | ⚠ "cerrá uno de los `claude`" |

Cada fila muestra la evidencia y su antigüedad ("según Stop hace 2 min"), como la vista Chat.

## 6. Control Directo (avanzado)

- En el panel del agente: botón secundario **Control directo** que abre la sesión en la vista Chat
  con el composer 3.2, con un aviso fijo: "Escribe en el terminal del agente. Usalo para destrabar o
  diagnosticar; los mensajes normales van por el chat del proyecto".
- El chat del proyecto muestra un marcador "Control directo · <fecha> · ver" cuando aparece un
  `composer_send` en la conversación del agente (sin copiar el texto).
- Mientras el monitor tenga una entrega en vuelo a ese agente, el Control Directo lo explica
  (precondición `monitor-delivery-in-flight`, roadmap P6) en lugar de competir.

## 7. Mobile

- Una columna: chat; el roster es una hoja inferior (igual que Agentes en 3.1); el selector de
  menciones es una hoja.
- La barra inferior de vistas del shell v2 no cambia; Proyectos entra por el sidebar/menú.
- El teclado virtual usa el offset de visual viewport ya resuelto en #506.

## 8. Accesibilidad

Chips con texto (no sólo color/ícono), `aria-live="polite"` sólo para cambios de estado de mensajes
propios, foco en el composer tras enviar, tarjetas navegables por teclado.

## 9. Fuera de alcance

Hilos anidados, reacciones, tareas con columnas, búsqueda global, notificaciones push nuevas.
